## BLOCKING findings

### B-1 · Packaging invented a second definition of "open"; an expired risk acceptance does not block it
`src/app/package-actions.ts:80` —
```ts
const settled = new Set(dispositions.map((d) => d.findingId));
...
openFindings: findings.filter((f) => !settled.has(f.id)).length,
```
Any disposition row at all counts as settled. It never calls `findingIsOpen()`
(`src/lib/submission.ts:317`), which is the one rule §4.3 mandates and whose own
docstring says *"Packaging, the queue and the obligation count all ask this one
function, so they can never disagree."* That sentence is false as written — the
same failure mode as G-65 ("written before it was true").
`src/app/(app)/projects/[id]/review/page.tsx:186` is the **only** caller.

**Reproduced live**, on a clone of the dev DB with Meridian's acceptance expiry
moved 10 days into the past:

| Surface | Same project, same moment |
|---|---|
| Review queue | `.rail-flag` → **`["BREACHES POLICY"]`** — finding open |
| Package page | **"Ready to package."** — and it packaged |

Control run on the unexpired dev DB: `.rail-flag` → `[]`. The only variable was
the expiry.

A risk-accepted disposition with `expires_at IS NULL` is the same bug
(`findingIsOpen` → open; packaging → settled).

**Fix:** pass `dispositionsFor` rows through `findingIsOpen(disposition, now)` in
`packageState`, exactly as the review page does. Add a unit test for the expired
case, and one integration test.

### B-2 · The screen is not demo-ready at any laptop width — content renders in a 240px column
`src/app/(app)/projects/[id]/package/page.tsx:61` wraps the page in
`<div className="assess-layout">` with a **single** `<section>` child.
`.assess-layout` (`src/app/styles/assess.css:2`) is
`grid-template-columns: 15rem minmax(0, 1fr)` — it expects an
`<aside class="rail">` first. All four other users of that class supply one; this
page does not, so its entire content lands in the 15rem rail column.

Measured on the running dev server at 1440×900:
```
GRID: {"cols":"240px 860px","contentWidth":240}
```
860px of the viewport is empty. The heading "Ready to package." wraps to two
lines; body copy wraps at 4–6 words. Same on the blocked state. Screenshots:
`/tmp/pkg-final-1440.png`, `/tmp/pkg-viewport-1440.png`, `/tmp/pkg-blocked-1440.png`,
`/tmp/pkg-ready-full.png`.

Fails §23(3) "hierarchy reads at a glance" and §23(7) "responsive to a laptop
viewport". This is precisely the class of defect `/ui-craft` says is caught by
reading a screenshot — no screenshot appears to have been read.

**Fix:** drop `assess-layout` (there is no rail on this screen) or give the
section `grid-column: 1 / -1`.

### B-3 · The stepper marks stage 4 complete when nothing has been packaged
`package/page.tsx:58` passes `currentStage={4}`. `STAGES` in
`project-header.tsx:11` has four entries, indices 0–3, and the state rule is
`i < currentStage ? "done" : i === currentStage ? "current" : "upcoming"`. Every
other page passes a valid index (0, 1 or 2); 4 is out of range.

Observed on the package page, ready **and** blocked:
```
STEPS: ["step done","step done","step done","step done"]
aria-current count: 0
```
On **Novara** — status pill "Draft", never submitted, blocker "This has not been
submitted yet" — the stepper still shows **✓ Package · signed, replayable
export**, plus ✓ on Assess and Review & attest. Visible in
`/tmp/pkg-blocked-1440.png`.

Two failures: §24.8 (the journey is shown dishonestly — a stage that has not
happened reads as done, the exact inversion of the law), and §23(5) (no stage
carries `aria-current="step"`, so a screen-reader user has no position in the
stepper — every other screen provides it).

**Fix:** `currentStage={3}`.

### B-4 · The refusal names counts, never questions (§19)
§19: *"Packaging with any visible unattested question fails, **naming questions
by text**."* `blockers()` in `src/lib/packaging.ts:110` computes `waiting` as a
count and discards which questions they were, even though `input.required` and
`input.attested` are both in hand. Observed on Sable: *"4 control answers have
not been attested."* The names — Multi-Factor Authentication, Access Review &
Recertification, Privileged Access Management, Remote Access — exist and are not
shown. `test/unit/packaging.test.ts` asserts the count wording, so the criterion
is encoded wrong in the test too.

### B-5 · The page's server-failure state is a bare sentence with no reference, no next step, and no way out
Forced by revoking `SELECT ON packages` in a sandbox. The entire `<main>`:
```

I couldn't assemble that just then.
```

`packageState`'s catch branch calls `failure(...)` **without** `expected: true`,
so a `ref` is generated and logged — and `package/page.tsx:38` renders only
`state.message`, dropping it. Violates §25.2 (reference must be shown —
`settle-finding.tsx:222` does this correctly), §25.3 (says nothing about whether
work is safe or what to do), §25.5 (rendered as an `<h1>`, not announced; and
*"every error path has a test"* — there is none). The person is stranded with no
link anywhere. `/tmp/pkg-error.png`.

The same drop happens in `package-view.tsx:76` for `makePackage`'s catch branch
("I couldn't record that just then.").

### B-6 · The mandated demo reset destroys the only packageable assessment
`scripts/seed-finished.mjs` (419 lines, added by this commit) creates "Meridian
contract intelligence" — the only assessment that can reach stage 4. It is wired
into **nothing**: not `demo:seed`, not `demo:reset`, not
`scripts/walk-demo.mjs`'s `reset()`, which run
`reset-dev-db.mjs && seed-demo.mjs` only.

`pnpm walk:demo` was run (G-70: *"runs before the demo, without exception"*). It
reset the database, and Meridian was gone — 4 projects left, none packageable.
Stage 4 then demos as "Not ready yet" for every assessment on the machine.

Compounding it: `seed-finished.mjs:30` reads `process.env.DATABASE_URL`

own header documents `node scripts/seed-finished.mjs`; run exactly that way it
throws `Error: DATABASE_URL is not set`.

**Fix:** add `process.loadEnvFile(".env")`, add a `demo:finished` script, and
append it to `demo:reset` and `walk-demo.mjs`'s `reset()`.
