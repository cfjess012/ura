# UAT — S4 · Tier 2 (severity)

**Done when:** §19 criteria; a Medium/High answer reveals its conditionals; a derived band routes.

### FR-6 — Tier-2 severity presents Low/Medium/High rubric anchors as the answer options

- **What was done:** Walked the demo scenario (AI rostering tool, vendor, confidential employee data) to Tier 2 and answered the Third-Party area.
- **What was observed:** Each question shows three cards and the card *is* the anchor — "Privileged / admin access to production and/or broad access across environments", not the word "High". Twenty-six questions carry seventy-eight anchors, all taken verbatim from the owner's own instrument. The band name and a tick both appear on the chosen card, so the state is never colour alone. Questions are paced one area per screen with a rail showing "1 of 4" per area.
- **Result:** pass
- **Evidence:** `test/unit/severity.test.ts` asserts every band on every question has an anchor over ten characters and spot-checks two against the owner's exact wording; `e2e/severity.spec.ts` reads the anchor off the rendered card; screenshot in the slice review.

### FR-7 — Severity derivable from fact answers via declared mappings

- **What was done:** Reached "Data Classification Handled" having told intake the data is Confidential, and inspected what the screen offered.
- **What was observed:** The question shows "Worked out for you — this looks like **Medium** because you told us the most sensitive data involved is Confidential." The suggestion is dashed rather than filled and **nothing is selected**: it is offered, never pre-answered, so the person's click is still the answer. The mapping is declared in `severity.json`, so the sentence shown and the fact used are the same thing. A list takes the worst member, not the first.
- **Result:** pass
- **Evidence:** `test/unit/severity.test.ts` covers the mapping, the worst-of-a-list rule, and that an unanswered fact derives nothing; `e2e/severity.spec.ts` asserts no radio is checked while the suggestion is visible.

### FR-8 — Conditionals: severity-fired, always-fired, cross-tier, nested

- **What was done:** Answered Provider Access at each band and watched what appeared; checked which questions exist at all under different Tier-1 answers.
- **What was observed:** **Severity-fired** — "Which access types apply?" appears at Medium and High, not at Low, and says "Shown because you answered High". **Cross-tier** — the question only exists because the Tier-1 path *Third-Party Logical Access* is lit; close the gate and it is not asked. **Always-fired** — Business Criticality, Breadth of Deployment and Access & Output Audience are asked whatever is lit. **Nested** — ticking "Admin / privileged" inside the fired detail requires two further controls of its own. Dropping the band back to Low hides the detail again.
- **Result:** pass
- **Evidence:** one test per kind in `test/unit/severity.test.ts`; `e2e/severity.spec.ts` drives the appear-and-disappear against rendered DOM.

### NFR-10 — State never conveyed by colour alone; flow fully keyboard-operable

- **What was done:** Checked every state on the severity screen and operated it without a mouse.
- **What was observed:** A chosen band carries a tick, a heavier border and an inset rule as well as a tint; a suggested band is dashed. The bands are a `radiogroup` labelled by the question text, with `aria-checked` on each option, so a screen reader hears the state. The detail group is labelled by its own question. Focus is visible. Saving, saved and failure all speak through a live region.
- **Result:** pass
- **Evidence:** screenshot; the markup uses `role="radio"`/`aria-checked` rather than colour; the same anchored-scale pattern was already keyboard-verified for the classification question in S2.

## Findings

- **The control workplan is computed, never stored.** Answering a band accumulates control objectives with every reason that pulled them in — "Level of Provider Access is High — privileged access mgmt" — and the summary recomputes the whole list from the answers. Change a band and the workplan changes with it, no migration.
- **§19's "both reasons retained" holds here too.** Two questions requiring the same control keep both reasons rather than collapsing to the first; there is a test for the shared objective between Provider Access and Privileged Access Risk.
- **FR-5 was claimed met here and was NOT met. Corrected 2026-08-21.** This record said `conditionSentence()` renders any condition as one English sentence. It did — to nobody. Independent verification found the function had no caller anywhere in `src/`, alongside `contradictions()` and `isSatisfiable()`: three exported functions with unit tests and no surface, which reads as coverage and is not. `demo/readiness.md` had said the honest thing all along ("FR-5's condition renderer does not exist; explanations are authored, not generated"), so two records of the same system disagreed and the optimistic one was the one being cited. All three functions are now deleted. **FR-5 remains unmet and carries forward** — the sentences a person actually reads are still hand-authored strings.
- **The contradiction lint's structural half is in the validators, not in a lint.** Unsatisfiable references, chained derivations and rules naming things that do not exist are rejected at boot by `validate()` in both instrument modules. The `contradictions()` helper that this record cited was never wired to anything and is deleted; the semantic half stays registered as an agentic opportunity and deliberately unattempted.
- **Lessons from S3 applied up front — half true, and the missing half was blocking.** The submission is validated whole and written in one transaction, and only questions the person touched are autosaved. But **submitting** the screen wrote every detail question in the group, hidden or not: an empty list is the substantive answer "none of these apply", so pressing the forward control on an untouched screen recorded a positive answer nobody gave, permanently, in an insert-only store. That is G-42 one tier down. Found by independent verification (B2), fixed, and the rule now lives in the pure module where `writableSeverityAnswers` tests can reach it.

## Agentic opportunity

**Registered, not built:** *Policy-grounded suggestions* (§22.1) — where a band maps to a published standard, the agent proposes it citing the clause that defines the standard and the requester's own words that meet it. FR-7's declared mappings are the deterministic version of the same idea and stay deterministic; the agent's job is the cases a table cannot express.

Deliberately **not** agentic: the rubric anchors, the thresholds, and the accumulation. A band decides which controls an organisation must evidence; that has to be reproducible and defensible, and "the model said Medium" is neither.
