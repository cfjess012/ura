### FR-19 — Packaging blocked until all visible attested, zero open findings

- **What was done:** Opened the package screen on an assessment with four unsigned controls and three open findings; on a Draft reached by URL rather than by a link; and on a fully attested, fully settled assessment. Then forced the case the gate exists for: an assessment whose only open finding was a **risk acceptance past its expiry**, reached the way the product reaches it — a newer acceptance inserted over an older one, since dispositions are insert-only. The gate was also attacked directly, by replaying the server action against a blocked assessment.
- **What was observed:** **First pass: FAIL, and this was the blocking one.** The gate counted disposition *rows* — any settlement at all meant settled — instead of asking `findingIsOpen()`, the one function §4.3 puts that decision in. So an expired acceptance packaged. Reproduced side by side on one assessment at one moment: the review queue showed `Breaches policy` while the package screen said "Ready to package", and it packaged. `findingIsOpen`'s own docstring already claimed packaging asked it, which was false when written. **Fixed:** the decision moved into pure `openFindingNames()` and the gate asks it; re-run, both surfaces now say the same thing and the package screen names `API & Interface Security` as outstanding. Separately the refusal named only counts — "4 control answers have not been attested" — where §19 requires questions **by text**; it now names Multi-Factor Authentication, Access Review & Recertification, Privileged Access Management and Remote Access, in the sentence and as a list, each with a link to where the work is done. A Draft is refused with one cause, not three symptoms of it. The forged action was refused server-side: `{"ok":false,"message":"This can't be packaged yet…","retryable":false}` — the gate is not the button.
- **Result:** pass
- **Evidence:** `test/unit/packaging.test.ts` — "AN EXPIRED ACCEPTANCE IS OPEN, and it blocks packaging", plus a source-level rule, "every reader of `dispositionsFor` reaches `findingIsOpen`", with a guard that fails if it stops covering more than one caller; `e2e/package.spec.ts` — the refusal names questions by text, and the Draft refusal; verifier transcript with the replayed `Next-Action` request; `audits/S9-verify-2026-08-26.md` (B-1, B-4).

### FR-20 — Insert-only replayable export; N-A exported as explicit reason strings

- **What was done:** Drove the full journey in the browser — intake, gates, severity, four control answers, submission, settling the policy breach with an owner and a date, and signing all four controls with one signed **Not applicable**. Read the payload, recorded it, recorded it a second time. Attacked the table directly: `UPDATE` and `DELETE` against `packages`, and a package with no answers. Then published a **new activated edition** of `tier1-gates` underneath a recorded assessment to see whether its provenance moved.
- **What was observed:** The payload carries every attested value with the person who signed it, the coverage of what was asked and why including the areas ruled out, and each finding with how it was settled. An N-A is the string `"value": "N-A"` with a required note, never a blank — a missing key would read as "never asked" when it means "asked, and does not apply". Re-export inserted a second record and left the first untouched. `UPDATE` and `DELETE` both raise `packages are insert-only (SPEC 4.5)`; a package with no answers is refused by `packages_have_answers`. **Provenance was wrong on the first pass** and this was the subtler defect: it named the *currently activated* editions, which is the right answer right up until the instrument is re-versioned — the one moment a reader needs it. Publishing `tier1-gates 9999.9` moved the active edition and, before the fix, would have moved the record's own account of what asked it. **Fixed:** provenance now reads what each answer pinned (`instrument_version_id`, NOT NULL since NFR-11), as a list rather than a map by slug, because an assessment answered across an edition boundary genuinely used two. Re-run with the new edition published: active moved to `9999.9`, provenance stayed `tier1-gates 2026-08-21.7`.
- **Result:** pass
- **Evidence:** `e2e/package.spec.ts` — "the full journey ends in a record another system can replay", covering N-A strings, non-empty attested values, coverage, provenance editions, settled findings, and re-export adding a record; `test/integration/invariants.test.ts` — "packages are insert-only" (4 tests: well-formed, no-answers refused, UPDATE/DELETE refused, first byte-identical after a second); `test/unit/packaging.test.ts` — "which instrument editions actually asked these questions" (5 tests, including supersession and the cross-boundary case); live re-versioning transcript 2026-08-26.

## Findings

**The verifier returned FAIL with six blocking findings and it was right on
all six.** The one worth carrying forward is **B-1**, and it is a sibling of
G-60 and G-65: _a shared predicate is only shared if every caller actually
calls it._ The rule existed, was correct, was documented as universal — and

offered no navigation at all (B-5); and `seed-finished.mjs` was wired into

## Agentic opportunity

**None, deliberately, and it is the honest answer here.** Packaging is
assembly, not judgement: every value in the payload is one a person gave or
a reviewer signed, and the coverage is the instrument's own account of what
it asked. A model that summarised, ranked or narrated any part of it would
be putting an unattested sentence inside a record whose entire purpose is
that a named person stands behind every line.

Nothing is foreclosed. The natural agentic surface sits *after* this one —
mapping an assembled payload onto a destination system's fields (§4.5,
§27) — and the payload is a stable, versioned document precisely so that
work can be done against it later without touching the gate.
